# AGENTS.md

## О проекте

`zombi-stalker` — небольшая браузерная 2D survival-horror игра про полицейский участок. Игрок собирает три улики, избегает зомби и добирается до выхода. Игра работает без нейросетей: поведение зомби построено на конечном автомате и обычном поиске пути.

## Технологии и структура

- Node.js 22+, pnpm.
- React 19, Next.js 16 и Vinext.
- `app/page.tsx` содержит игровое состояние, карту, управление, AI и отрисовку Canvas.
- `app/globals.css` содержит визуальный стиль и адаптивную вёрстку.
- `next.config.ts` настраивает статический экспорт и пути GitHub Pages.
- `.github/workflows/pr-preview.yml` публикует отдельное превью каждого Pull Request.
- `.openai/hosting.json` относится к существующему проекту OpenAI Sites. Не создавайте новый Sites-проект и не меняйте production-деплой без явного запроса пользователя.

## Игровые правила, которые нельзя ломать

AI зомби должен сохранять пять понятных состояний:

1. Игрок не обнаружен → зомби бродит по участку (`wander`).
2. Зомби слышит шум → идёт к его источнику (`investigate`).
3. Игрок попал в поле зрения → зомби преследует его (`chase`).
4. Зомби потерял игрока → проверяет последнее известное место (`search`).
5. Зомби догнал игрока → атакует (`attack`), после чего продолжает погоню или поиск.

После неудачного поиска зомби обязан вернуться к обычному блужданию. Стены должны блокировать движение и обзор. Выход открывается только после сбора трёх улик.

## Правила разработки

- Сохраняйте игру одностраничной и запускаемой без сервера после статической сборки.
- Не добавляйте нейросети, внешние AI API, базу данных или обязательную регистрацию.
- Не переносите игровой цикл из Canvas без веской причины.
- Новые состояния AI должны иметь видимое название и понятное правило в интерфейсе.
- Поддерживайте клавиатуру: WASD/стрелки — движение, Shift — бег и шум, Space — отвлечение, P — пауза.
- Сохраняйте рабочее управление кнопками на мобильных экранах.
- Не редактируйте сгенерированные каталоги `.next`, `.vinext`, `.wrangler`, `dist` и `node_modules` вручную.
- Не удаляйте корневой `.nojekyll` из ветки `gh-pages`: без него GitHub Pages скрывает каталог `_next`, и игра загружается без стилей и JavaScript.

## Проверка изменений

Перед завершением задачи выполните:

```bash
pnpm lint
pnpm build
```

Для изменений игрового процесса дополнительно проверьте в браузере:

- карта, игрок и зомби отрисовываются;
- движение и столкновения со стенами работают;
- зомби переходит между `wander`, `investigate`, `chase`, `search` и `attack`;
- можно собрать три улики и выйти;
- проигрыш, пауза и перезапуск работают;
- в консоли браузера нет ошибок.

## Pull Request и превью

- Работайте в отдельной ветке и не отправляйте изменения напрямую в `main`, если пользователь явно не попросил обратное.
- После push дождитесь успешного workflow `Deploy Pull Request preview`.
- Адрес превью имеет вид `https://kiraobezjanka-sudo.github.io/zombi-stalker/pr-preview/pr-<номер>/`.
- Проверяйте опубликованную страницу визуально: успешный workflow сам по себе не гарантирует загрузку CSS и JavaScript.
- Не объединяйте Pull Request без явного запроса пользователя.
